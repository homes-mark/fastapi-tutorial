# FastAPI 由浅入深完整学习教程（28 法则版）

> 一份面向 Python 开发者的中文 FastAPI 教程：从接口基础开始，逐步学习数据校验、依赖注入、异步编程、数据库、认证授权与部署，并用“20% 主干优先”的路线和一个业务纵切面把核心能力真正串起来。示例项目统一使用 uv 管理依赖。

## 这个教程是为了什么？

FastAPI 不只是“用几行代码写出一个接口”。真正投入项目后，还需要处理数据校验、依赖复用、异步并发、数据库访问、安全认证、后台任务和部署等问题。

本教程希望帮助读者：

- 识别一个 FastAPI 项目中真正承载核心业务风险的 20% 模块；
- 建立 FastAPI 的完整知识体系，而不是只记住零散的装饰器用法；
- 理解每个核心机制解决的问题，以及它们之间的演进关系；
- 通过可运行示例和练习，把概念转化为实际编码能力；
- 从简单 CRUD 逐步完成一个接近生产环境的 API 项目。

教程不依赖在线文档或 CDN，所有页面均可离线阅读，适合系统学习、课后复习或作为项目参考。

## 先读这一节：28 法则怎么落地

帕累托法则在这里是**学习顺序**，不是跳过难点。一个项目里，少数模块承载大部分业务逻辑与线上风险。建议先把下面五段主干打通：

1. **请求契约**：路由、路径/查询参数、请求体、状态码与响应模型；
2. **Pydantic 边界**：创建/更新/内部/公开模型分离，校验与序列化白名单；
3. **依赖与会话**：当前用户、数据库会话、配置、清理和测试替换；
4. **认证与数据隔离**：JWT、401/403、`owner_id` 查询与 IDOR 防护；
5. **异步任务边界**：`def`/`async def`、`BackgroundTasks`、消息队列的取舍。

推荐路线：

```text
第 1 章 → 第 2–3 章 → 第 4 章 → 第 8 章 → 第 9 章
→ 第 6 章 → 核心纵切面 → 第 7 章 → 第 5 章
→ 第 10 章 → 四个阶段项目
```

先完成“核心路线 · 20% 主干业务纵切面”，再按真实需求补 WebSocket、文件处理、Celery、压测、CI/CD 和容器编排。

### 实战篇：完成一个逐步演进的 API 项目

实战项目按四个阶段递进，每一阶段都会在上一阶段基础上增加新的工程能力：

1. **阶段一：单模块 CRUD**——完成用户与商品的基本增删改查；
2. **阶段二：多模块与数据库**——拆分项目结构，接入 SQLAlchemy 和数据模型；
3. **阶段三：认证与后台任务**——加入 JWT 登录、权限校验和异步任务；
4. **阶段四：企业级完善**——补充安全、测试、可维护性与部署能力。

## 示例版本

教程原有示例主要基于 FastAPI 0.110 系列；新增内容采用当前推荐的 FastAPI CLI、SQLAlchemy 2.0、Pydantic 2、`pwdlib` 和 PyJWT 写法。示例项目统一使用 uv 管理环境与依赖：

```bash
uv init --app fastapi-demo
cd fastapi-demo
uv add "fastapi[standard]"
uv run fastapi dev main.py
```

`pyproject.toml` 声明直接依赖，`uv.lock` 记录完整解析结果，两者都应提交到 Git。团队协作和 CI 使用 `uv sync --frozen` 还原环境，使用 `uv run <command>` 运行项目。需要精确固定 FastAPI 版本时，可执行 `uv add "fastapi[standard]==0.141.1"`。

实际开发时请同时参考所使用版本的官方文档，并使用环境变量或密钥管理服务保存敏感配置。示例中的安全代码用于教学，上线前仍需结合威胁模型做限流、日志脱敏、密钥轮换、依赖审计和真实数据库测试。
