第 7 章 · 异步编程 async/await

难度：高级 前置：第 1–6 章 预计：60 分钟

🎯 本章学习目标

  • 理解同步阻塞 vs 异步并发的本质区别；
  • 掌握事件循环、async def、await 的基本概念；
  • 知道何时该用 async def 路由、何时不该用（关键！）；
  • 理解 FastAPI 如何调度异步与同步路由。

📚 前置知识

前 6 章。对「阻塞 I/O」有基本体感即可。

7.1 为什么要异步

Web 服务的瓶颈往往不是 CPU，而是 I/O 等待：读数据库、调第三方 API、读写文件，都要等。同步模式下，进程在等待时什么也做不了；异步模式则能在等待时切换到别的任务，大幅提升并发吞吐。

📖 事件循环（Event Loop）

异步编程的核心是一个「事件循环」：它维护一批任务，遇到 await 挂起当前任务、去执行别的任务，等被挂起的 I/O 完成后再回来继续。这一切在单线程里完成，靠「协作式切换」而非多线程抢占。

7.2 基本语法

main.py
import asyncio


async def fetch_data():
    # 模拟异步 I/O（如数据库查询、HTTP 请求）
    await asyncio.sleep(1)
    return "数据"


@app.get("/data/")
async def read_data():
    result = await fetch_data()   # 挂起，让出控制权
    return {"result": result}
  • async def：声明一个协程函数；
  • await：挂起当前协程，等待一个可等待对象（awaitable）完成；
  • 只有真正异步的库（如 httpx.AsyncClient、asyncpg、aiosqlite）才能从 await 中获益。

7.3 关键：async 路由与阻塞的陷阱

这是 FastAPI 异步编程最容易踩的坑。看下面两个对比：

反模式：async 里放阻塞代码
import time

@app.get("/slow/")
async def slow_endpoint():
    time.sleep(5)   # ❌ 阻塞！整个事件循环被卡住 5 秒
    return {"done": True}

time.sleep 是同步阻塞的，即使函数是 async def，它也会卡住整个事件循环，期间所有请求都无法处理。

正确做法
import asyncio

@app.get("/slow/")
async def slow_endpoint():
    await asyncio.sleep(5)  # ✅ 异步等待，让出控制权
    return {"done": True}
⚠️ 黄金法则

如果路由里只有同步阻塞代码（如普通 requests、同步 sqlalchemy、CPU 密集计算），就别用 async def，用普通 def。FastAPI 会把同步路由放到线程池里执行，反而能避免阻塞事件循环。反过来，用了异步库（httpx.AsyncClient 等）才用 async def。

场景推荐写法
纯 CPU 计算 / 同步库调用def（进线程池）
异步 I/O（async 库）async def
async 里混入少量阻塞用 run_in_threadpool 包裹

7.4 异步 HTTP 客户端

main.py
import httpx

@app.get("/proxy/")
async def proxy():
    async with httpx.AsyncClient() as client:
        resp = await client.get("https://api.example.com/data")
    return resp.json()

依赖版本：httpx==0.27.0。用 AsyncClient 才能在 await 中非阻塞地发请求。

🔗 概念关联：异步是贯穿后面所有章节的「性能底座」。第 8 章的异步数据库驱动（asyncpg/aiosqlite）、第 10 章的 WebSocket（天然异步）都建立在本章的事件循环之上。

7.5 动手练习

练习 1 · 观察阻塞★★ 中等

写两个路由：一个 async def 里用 time.sleep(5)，另一个普通 def 快速返回。先访问慢路由，再立刻访问快路由。

验证方法：慢路由的 time.sleep 会阻塞事件循环，导致快路由也要等 5 秒才响应——这正是「async 里放阻塞代码」的危害。
练习 2 · 正确异步等待★★ 中等

把练习 1 的 time.sleep(5) 改成 await asyncio.sleep(5)，重复测试。

验证方法：快路由这次立即返回，不再被慢路由阻塞。
练习 3 · 并发请求★★★ 较难

用 asyncio.gather 并发调用 3 个异步函数，对比顺序执行的总耗时。

验证方法：并发总耗时 ≈ 单个任务耗时，而非三倍。
💡 最佳实践

先判断「这个 I/O 是异步库吗？」——是，用 async def + await；不是，用普通 def。不要在 async def 里混入 time.sleep、同步 requests、CPU 密集循环。这是把高性能 FastAPI 写慢的第一大原因。
