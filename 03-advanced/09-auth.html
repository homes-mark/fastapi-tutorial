第 9 章 · 身份认证与授权

难度：高级 前置：第 4、8 章 预计：75 分钟

🎯 本章学习目标

  • 区分「认证（Authentication）」与「授权（Authorization）」；
  • 掌握 OAuth2 密码流与 JWT 的基本原理与实现；
  • 学会用 passlib 安全地哈希存储密码；
  • 用依赖注入实现 get_current_user 保护路由。

📚 前置知识

第 4 章依赖注入、第 8 章数据库。了解 HTTP 头、Base64 编码。

💡 依赖版本

本章使用 python-jose[cryptography]==3.3.0（JWT）、passlib[bcrypt]==1.7.4（密码哈希）、python-multipart==0.0.9（OAuth2 表单）。

9.1 认证 vs 授权

  • 认证（Authentication）：确认「你是谁」——登录、验证密码、签发令牌；
  • 授权（Authorization）：确认「你能做什么」——某个用户能否访问某个资源。

两者常被混为一谈，但流程上通常是：先认证拿到身份，再基于身份做授权判断。

9.2 密码哈希（绝不存明文）

security.py
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")


def hash_password(password: str) -> str:
    return pwd_context.hash(password)


def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)

数据库里永远只存 hash_password() 的结果，登录时用 verify_password() 比对。这样即使数据库泄露，攻击者也拿不到明文密码。

9.3 JWT 令牌

JWT（JSON Web Token）是一种无状态令牌：服务器签发后，客户端携带它，服务器通过签名验证真伪，无需存 session。

security.py
from datetime import datetime, timedelta
from jose import jwt

SECRET_KEY = "your-secret-key"     # 生产环境应从环境变量读取
ALGORITHM = "HS256"
EXPIRE_MINUTES = 30


def create_access_token(data: dict) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)


def decode_token(token: str):
    return jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
⚠️ 安全红线

SECRET_KEY 绝不能硬编码在代码里提交到仓库——要用环境变量或密钥管理服务。JWT 过期时间要设短，敏感操作要二次校验。不要在 JWT 里放密码等敏感信息（它是可解码的，只是不可篡改）。

9.4 用依赖注入保护路由

main.py
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")


def get_current_user(token: str = Depends(oauth2_scheme)):
    try:
        payload = decode_token(token)
        username = payload.get("sub")
        if username is None:
            raise HTTPException(401, "无效令牌")
        return {"username": username}
    except Exception:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "令牌无效或过期")


@app.get("/users/me")
def read_me(current_user=Depends(get_current_user)):
    return current_user

现在任何带 Depends(get_current_user) 的路由，都会自动要求合法令牌。这和第 4 章的 verify_api_key 是同一个模式，只是升级成了标准的 OAuth2 + JWT。

📖 OAuth2 密码流

FastAPI 的 OAuth2PasswordBearer 实现了「密码流」（Resource Owner Password Credentials）。它让 /docs 里的「Authorize」按钮可用：填入用户名密码换取 token，再带着 token 调接口。这是入门理解 OAuth2 的最佳切入口。

9.5 授权：角色权限

授权示例
def require_role(role: str):
    def checker(current_user=Depends(get_current_user)):
        if current_user.get("role") != role:
            raise HTTPException(403, "权限不足")
        return current_user
    return checker


@app.get("/admin/")
def admin_only(user=Depends(require_role("admin"))):
    return {"message": "仅管理员可见"}

通过「依赖工厂」require_role，可以灵活地给不同路由绑定不同权限要求。

🔗 概念关联：本章 = 依赖注入（第 4 章）+ 数据库（第 8 章）的合体。get_current_user 内部会查数据库拿用户，再用依赖注入保护路由。实战项目阶段三会完整落地「注册 → 登录 → 受保护接口」的闭环。

9.6 动手练习

练习 1 · 密码哈希★ 简单

用 hash_password / verify_password 分别验证「正确密码通过、错误密码拒绝」。

验证方法：打印 verify_password("123", hash_password("123")) 为 True，错误密码为 False。
练习 2 · 签发与验证 JWT★★ 中等

签发一个带 sub 和 exp 的 token，再解码验证；篡改一个字符后验证是否失败。

验证方法：合法 token 解码成功；篡改后的 token 抛异常（签名不匹配）。
练习 3 · 保护路由★★★ 较难

实现完整流程：/token 登录换取 token，/users/me 带 token 访问，不带则 401。

验证方法：不带 token 访问 /users/me 返回 401；带正确 token 返回用户信息。
💡 最佳实践

密码必哈希存储；SECRET_KEY 走环境变量；JWT 短过期 + 可选刷新令牌；用依赖注入统一鉴权而非在每个路由里写判断；敏感操作（改密码、删账号）单独二次验证。
